01 — System Overview

What We're Building

The ISL Vocalizer is a wearable glove that translates Indian Sign Language gestures into spoken words in real time. The software team owns everything from the moment sensor data leaves the ESP32 chip to the moment a speaker says the recognized word.

As the software team, you do not write the ESP32 firmware (that's the hardware team). You own everything after the USB cable:

  • ✗Flex sensor wiring and calibration

Important Handshake
The one thing both teams must agree on upfront is the serial data format — the exact structure of what the ESP32 prints over USB. Define this in week 1 and don't change it without informing both sides.

Agreed Serial Format (define with hardware team)

serial_format.txt UART 9600 baud 
# Each line the ESP32 prints — comma-separated, newline-terminated
# Format: thumb,index,middle,ring,pinky,ax,ay,az,gx,gy,gz

820,700,200,150,300,0.12,-0.05,9.81,12,-5,3

# Field breakdown:
# thumb, index, middle, ring, pinky  →  flex sensor ADC values (0–4095)
# ax, ay, az                          →  accelerometer (m/s²)
# gx, gy, gz                          →  gyroscope (degrees/sec)
# 11 values total per line
# Baud rate: 9600
# Line terminator: \r\n

03 — Phase 1

Serial Data Bridge

Week 1–2 pyserial Python

Your first task. The hardware team has the ESP32 printing sensor values over USB. You write the Python script that receives, validates, and logs this data. Everything downstream depends on this working correctly.

Phase 1 Flowchart

Serial reader decision flow

The Code

serial_reader.py Python 
import serial
import csv
import time

# ── CONFIG ─────────────────────────────────────────────────────
PORT     = 'COM3'          # Windows: COM3  |  Linux/Mac: /dev/ttyUSB0
BAUDRATE = 9600
COLUMNS  = ['thumb','index','middle','ring','pinky',
            'ax','ay','az','gx','gy','gz']

# ── OPEN CONNECTION ─────────────────────────────────────────────
port = serial.Serial(PORT, BAUDRATE, timeout=1)
print(f"Connected to {PORT}. Listening...")

with open('raw_data.csv', 'w', newline='') as f:
    writer = csv.writer(f)
    writer.writerow(COLUMNS)          # header row

    while True:
        try:
            raw  = port.readline().decode('utf-8').strip()
            vals = raw.split(',')

            if len(vals) != 11:
                print(f"[WARN] Bad line: {raw}")
                continue

            row = [float(v) for v in vals]
            writer.writerow(row)
            print(row)               # live feedback

        except ValueError:
            print("[WARN] Non-numeric value, skipping")
        except KeyboardInterrupt:
            print("\nStopped. Data saved to raw_data.csv")
            break
How to find your COM port
Windows: Open Device Manager → Ports (COM & LPT) → look for "CP210x" or "CH340". Linux/Mac: run ls /dev/tty* in terminal before and after plugging the ESP32 — the new entry is your port.

Data Collection Tool

collect_data.py Python 
import serial, csv, time, os

PORT     = 'COM3'
BAUDRATE = 9600
SAMPLES  = 60     # minimum 60 per gesture
GESTURES = ['YES','NO','HELP','STOP','PLEASE','WATER']
OUTFILE  = 'dataset.csv'

COLUMNS  = ['thumb','index','middle','ring','pinky',
            'ax','ay','az','gx','gy','gz','label']

port = serial.Serial(PORT, BAUDRATE, timeout=1)
write_header = not os.path.exists(OUTFILE)

with open(OUTFILE, 'a', newline='') as f:
    writer = csv.writer(f)
    if write_header:
        writer.writerow(COLUMNS)

    for gesture in GESTURES:
        input(f"\n► Get ready to sign '{gesture}'. Press ENTER when ready...")
        print("  3..."); time.sleep(1)
        print("  2..."); time.sleep(1)
        print("  1... GO!"); time.sleep(0.5)

        count = 0
        while count < SAMPLES:
            raw  = port.readline().decode('utf-8').strip()
            vals = raw.split(',')
            if len(vals) == 11:
                try:
                    row = [float(v) for v in vals] + [gesture]
                    writer.writerow(row)
                    count += 1
                    print(f"  [{count}/{SAMPLES}]", end='\r')
                except ValueError:
                    pass

        print(f"\n  ✓ {SAMPLES} samples saved for '{gesture}'")

print("\nDone! Dataset saved to dataset.csv")
Data Quality Rules
Record at least 60 samples per gesture. Record across multiple sessions (different days, different lighting). If possible, record with multiple people wearing the glove — different hand sizes produce different sensor values. Never mislabel — it poisons the model more than missing data.

ML training workflow — top to bottom

Step 2: Why normalization matters

Raw flex sensor values range from 200–4095. Accelerometer values are in m/s² (~0–10). If you feed these raw into a neural network, it treats the flex values (4095) as thousands of times more important than accelerometer values (9.8). Normalization rescales everything to 0–1 so the model treats all features equally.

train.py — Steps 1–4: Load, normalize, encode, split Python 
import pandas as pd
import numpy as np
import tensorflow as tf
import pickle
from sklearn.preprocessing import LabelEncoder, MinMaxScaler
from sklearn.model_selection import train_test_split

# ── STEP 1: Load ────────────────────────────────────────────────
df = pd.read_csv('dataset.csv')
X  = df.drop('label', axis=1).values   # shape: (n_samples, 11)
y  = df['label'].values

# ── STEP 2: Normalize to 0–1 ────────────────────────────────────
scaler = MinMaxScaler()
X_norm = scaler.fit_transform(X)

# ── STEP 3: Encode labels ───────────────────────────────────────
encoder = LabelEncoder()
y_enc   = encoder.fit_transform(y)        # YES→0, NO→1, HELP→2 ...
y_cat   = tf.keras.utils.to_categorical(y_enc)  # one-hot

# ── STEP 4: Train/test split ─────────────────────────────────────
X_train, X_test, y_train, y_test = train_test_split(
    X_norm, y_cat, test_size=0.2, random_state=42, stratify=y_cat
)

print(f"Train: {X_train.shape}, Test: {X_test.shape}")
print(f"Classes: {encoder.classes_}")

# ── Save preprocessing objects ───────────────────────────────────
pickle.dump(scaler,  open('scaler.pkl',  'wb'))
pickle.dump(encoder, open('encoder.pkl', 'wb'))

Step 5A: Static Gesture Model (Dense Neural Network)

train.py — Dense model for static gestures Python 
# Input: 11 sensor values → Output: gesture class probabilities
n_classes = len(encoder.classes_)

model = tf.keras.Sequential([
    tf.keras.layers.Dense(128, activation='relu', input_shape=(11,)),
    tf.keras.layers.Dropout(0.3),              # prevents overfitting
    tf.keras.layers.Dense(64,  activation='relu'),
    tf.keras.layers.Dropout(0.2),
    tf.keras.layers.Dense(32,  activation='relu'),
    tf.keras.layers.Dense(n_classes, activation='softmax')  # probability per class
])

model.compile(
    optimizer='adam',
    loss='categorical_crossentropy',
    metrics=['accuracy']
)

history = model.fit(
    X_train, y_train,
    epochs=80,
    batch_size=16,
    validation_data=(X_test, y_test),
    verbose=1
)

model.save('gesture_model_static.h5')

Step 5B: Dynamic Gesture Model (LSTM)

For moving gestures like "HI" or "BYE", a single snapshot of sensor values isn't enough. You need to capture the sequence of readings over time (~20 frames). LSTM (Long Short-Term Memory) networks are designed exactly for this — they understand patterns over time.

train_lstm.py — LSTM model for dynamic gestures Python 
# For dynamic gestures, collect 20 consecutive frames per sample
# X shape: (num_samples, 20, 11)  — 20 timesteps, 11 features each

TIMESTEPS = 20

# Reshape flat data into sequences (group 20 rows per gesture)
X_seq = X_norm.reshape(-1, TIMESTEPS, 11)
y_seq = y_cat[::20]           # one label per sequence

lstm_model = tf.keras.Sequential([
    tf.keras.layers.LSTM(64, return_sequences=True, input_shape=(TIMESTEPS, 11)),
    tf.keras.layers.LSTM(32),
    tf.keras.layers.Dense(32, activation='relu'),
    tf.keras.layers.Dense(n_classes, activation='softmax')
])

lstm_model.compile(optimizer='adam', loss='categorical_crossentropy', metrics=['accuracy'])
lstm_model.fit(X_train_seq, y_train_seq, epochs=60, validation_data=(X_test_seq, y_test_seq))
lstm_model.save('gesture_model_dynamic.h5')

Step 6: Evaluate Your Model

Never just look at accuracy. Use a confusion matrix to see exactly which gestures are being confused with each other.

evaluate.py Python 
from sklearn.metrics import classification_report, confusion_matrix
import seaborn as sns
import matplotlib.pyplot as plt

y_pred_probs = model.predict(X_test)
y_pred = np.argmax(y_pred_probs, axis=1)
y_true = np.argmax(y_test,       axis=1)

print(classification_report(y_true, y_pred, target_names=encoder.classes_))

cm = confusion_matrix(y_true, y_pred)
sns.heatmap(cm, annot=True, fmt='d',
           xticklabels=encoder.classes_,
           yticklabels=encoder.classes_)
plt.title('Confusion Matrix')
plt.show()
Overfitting Warning
If training accuracy is 99% but test accuracy is 70%, your model has memorized the training data and can't generalize. Fix: collect more diverse data, increase Dropout, reduce model size, or train for fewer epochs.
06 — Phase 4

TinyML Deployment to ESP32

Week 5–7 Edge Impulse TFLite

Your trained model lives on your laptop. This phase moves it onto the ESP32 microcontroller so it runs on-device — no Wi-Fi, no cloud, no laptop. This is called TinyML.

Two Paths to Deployment

Path A: Edge Impulse
Recommended

Web platform that handles the entire pipeline. Upload your dataset, train a model on their servers, download C++ Arduino library.

  • 1Create free account at edgeimpulse.com
  • 2Upload your CSV dataset
  • 3Design an impulse (processing blocks)
  • 4Train the model on their servers
  • 5Download "Arduino library" ZIP
  • 6Give ZIP to hardware team to flash
Path B: TensorFlow Lite
Full control

Convert your own trained model to a tiny format that runs on microcontrollers. More work, but you control every step.

  • 1Train model in TensorFlow (Phase 3)
  • 2Convert to .tflite (quantized)
  • 3Convert .tflite to C byte array
  • 4Embed array in ESP32 firmware
  • 5Hardware team flashes the firmware

Path B: TFLite Conversion Code

export_tflite.py Python 
import tensorflow as tf

model = tf.keras.models.load_model('gesture_model_static.h5')

# Convert and quantize (shrinks model size ~4x, speeds up inference)
converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_model = converter.convert()

with open('gesture_model.tflite', 'wb') as f:
    f.write(tflite_model)

print(f"Model size: {len(tflite_model) / 1024:.1f} KB")

# Convert to C header file for embedding in ESP32 firmware
# Run in terminal: xxd -i gesture_model.tflite > gesture_model.h
# Then give gesture_model.h to the hardware team

You hand the hardware team either: (A) the Edge Impulse Arduino library ZIP, or (B) the gesture_model.h C header file + scaler_params.h containing your normalization min/max values so the ESP32 can normalize inputs the same way you did during training.

Route B: Android Studio (Full App)

MainActivity.kt — Bluetooth TTS receiver Kotlin / Android 
class MainActivity : AppCompatActivity() {

    private lateinit var tts: TextToSpeech
    private var bluetoothSocket: BluetoothSocket? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // Init TTS on app launch (not per word — this is the key for low latency)
        tts = TextToSpeech(this) { status ->
            if (status == TextToSpeech.SUCCESS)
                tts.setLanguage(Locale.US)
        }

        connectBluetooth()
        startListening()
    }

    private fun startListening() {
        Thread {
            val reader = bluetoothSocket?.inputStream?.bufferedReader()
            reader?.forEachLine { word ->
                runOnUiThread {
                    tts.speak(word.trim(), TextToSpeech.QUEUE_FLUSH, null, null)
                    statusText.text = "Recognized: $word"
                }
            }
        }.start()
    }
}
Low-latency tip
Always initialize the TextToSpeech engine when the app opens, not when a word arrives. Cold-starting TTS per word adds 300–800ms of delay, which makes the glove feel broken even if the ML model is fast.

09 — Common Pitfalls

What Will Go Wrong (and How to Fix It)

These are the exact problems every team building this kind of project hits. Learn them now so you recognize them when they happen.

Model works on laptop, fails on real gestures

Cause: Training data was recorded in one session with one person, glove fit differently during demo. Fix: Record 100+ samples per gesture across multiple sessions and people. Add ±5% noise to training data artificially.

Two gestures keep getting confused

Cause: They produce similar sensor patterns. Find them using the confusion matrix. Fix: Collect 100 more samples of each specifically, on different days. Or physically redesign one of the signs to be more distinct.

High accuracy in training, low in real use

Cause: Overfitting — model memorized training samples. Fix: Increase Dropout to 0.4, collect more diverse data, train for fewer epochs, check that test set isn't contaminated with training samples.

Long delay between gesture and voice

Cause: Usually TTS engine cold-starting per word, or Bluetooth packet buffering. Fix: Init TTS on app launch. Flush Bluetooth buffer immediately on receipt. Check if serial baud rate is too slow.

Sensor values different between sessions

Cause: Flex sensors drift with temperature and repeated bending. Glove fits slightly differently each time. Fix: Add a calibration step at app startup — record 5 seconds of "flat hand" to set a baseline offset. Normalize relative to baseline, not absolute values.
